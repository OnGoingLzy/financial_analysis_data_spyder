# 同行对比报告期切换设计

## 目标

同行对比页面允许分析人员在所选公司的共同报告期之间切换。任一报告期下必须保持完整样本，不因部分公司缺少数据而静默减少样本，也不允许混用不同报告期。

## 数据口径

- 可选报告期为当前所选公司在 `income_statements` 中报告期的交集。
- 报告期按日期从新到旧排序。
- 默认使用最新共同报告期。
- 指定报告期变化后，营收、利润、资产负债、现金流、同行中位数、分位排名及全部图表必须使用同一个报告期重新计算。
- 期初资产负债数据仍按既有指标引擎规则寻找，不改变 ROE、周转率等指标口径。

## API 设计

扩展现有 `GET /api/compare` 响应，新增：

```json
{
  "availablePeriods": ["2026-03-31", "2025-12-31"],
  "commonPeriod": "2026-03-31"
}
```

服务端在查询同行数据前计算共同报告期：

1. 未传 `period` 时选择最新共同报告期。
2. `period` 属于共同报告期时使用该期间。
3. `period` 不再属于共同报告期时回退到最新共同报告期，并在响应中返回实际采用值。
4. 不存在共同报告期时返回现有 `NO_COMMON_PERIOD` 错误。

采用同一接口返回共同报告期列表，避免额外网络请求，并确保期间候选与实际计算使用同一服务端口径。

## 前端交互

- 在同行对比筛选工具栏中，将“报告期”选择器放在比较模式与“更新分析”按钮之间。
- 选项显示报告类型和截止日期，例如 `2026 一季报 · 2026-03-31`。
- 切换报告期后立即重新请求同行对比数据。
- 比较模式切换时保留当前报告期。
- 更新公司样本后，原期间仍有效则保留；失效时采用接口返回的最新共同报告期。
- 实际采用的报告期写入 URL 的 `period` 参数，页面刷新、复制链接和浏览器前进后退均可恢复状态。
- 请求处理中禁用报告期选择器和更新按钮。
- 候选列表只有一个期间时仍显示选择器，但保持禁用，明确当前分析口径。

## 状态与错误处理

- 请求失败时保留上一次成功结果，并展示现有错误状态。
- 用户快速切换期间时中止前一次请求，只接受最后一次响应。
- 接口回退报告期后，前端以响应的 `commonPeriod` 更新选择器和 URL，不显示虚假的旧选择。
- 不使用模拟期间，不把缺失报告期补成零。

## 测试与验收

### 服务端

- 多家公司共同报告期交集计算正确且按倒序返回。
- 未指定期间时采用最新共同报告期。
- 指定有效期间时返回该期间的数据。
- 指定非共同期间时回退到最新共同报告期。
- 无共同报告期时返回 `NO_COMMON_PERIOD`。

### 前端

- 报告期选择器展示接口返回的全部共同期间。
- 切换期间会发送包含 `period` 的请求。
- 比较模式切换保留期间。
- 服务端回退后 URL 与选择器同步到实际期间。
- 加载状态和单一期间状态下选择器正确禁用。

### 浏览器验收

- 在至少两个共同报告期之间切换，标题、状态行、图表和指标矩阵同步更新。
- 切换后控制台无错误，图表悬停仍显示对应期间的数值。
- 刷新带 `period` 参数的 URL 后保持相同报告期。

## 非目标

- 不支持将缺少指定报告期的公司排除后继续对比。
- 不支持跨报告期混合、自动插值或模拟缺失数据。
- 本次不改变单家公司分析页面的期间切换逻辑。
