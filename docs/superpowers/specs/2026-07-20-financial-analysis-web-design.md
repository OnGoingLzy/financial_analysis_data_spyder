# 企业财务深度分析 Web 系统设计规格

## 1. 文档信息

- 日期：2026-07-20
- 目标目录：`D:/workbench/python/financial_analysis_data_spyder/Web`
- 主要用户：公司内部财务分析人员
- 核心任务：同行横向对比、单家公司深入分析、向管理层汇报分析结论
- 视觉方向：专业克制的研究终端风
- 数据库：`D:/workbench/python/financial_analysis_data_spyder/financial_analysis.db`

## 2. 建设目标

在项目下新增一个可独立安装、启动、测试和构建的 Vue 3 应用。系统启动后由本地 Node 数据服务自动读取指定 SQLite 数据库，不展示模拟数据，也不要求用户上传或选择数据库文件。

新系统必须解决原纯 HTML 界面的主要问题：

1. 区分并消除模拟数据，不允许静默回退。
2. 按中国市场习惯统一为盈利和正增长红色、亏损和负增长绿色。
3. 修正季度累计值、单季度值、TTM 和报告期的表达口径。
4. 修正 ROE、财务费用负值、缺失值和同行共同期间等计算问题。
5. 提供高效的同行比较和单家公司分析工作流。
6. 增加数据来源、字段口径、数据质量和异常状态说明。
7. 实现基础桌面、平板和手机响应式布局，不允许固定侧栏挤压内容；移动端视觉验收优先级最低，由用户手工确认。
8. 提供键盘操作、焦点状态和图表文字替代。
9. 将原始文本财务数据标准化写入正式数据库表。

## 3. 总体架构

采用 `Web` 目录内自包含的 Vue 3 前端与 Node 本地数据服务：

- 前端：Vue 3、Vite、TypeScript、Vue Router、Pinia、ECharts。
- 数据服务：Node.js、Express、SQLite 驱动。
- 测试：Vitest、Vue Test Utils、Supertest；Python 侧使用 pytest。
- 开发模式：一个命令同时启动 Vite 和本地 API。
- 生产模式：先构建前端，再由 Node 服务同时提供静态资源和 `/api`。
- 数据库路径：默认固定为项目根目录的 `financial_analysis.db`，允许通过专用环境变量覆盖，但前端不提供切换入口。

浏览器不直接读取数据库文件。Node 服务负责数据库连接、参数校验、共同报告期选择、指标计算和标准化 JSON 输出。

## 4. 视觉与交互系统

### 4.1 Hallmark 方向

- 类型：现代极简的技术研究界面。
- 宏观结构：Workbench 工作台。
- 主题：Terminal 研究终端。
- 导航：桌面端侧边导航，窄屏收起为顶栏菜单。
- 数据署名：侧栏底部展示数据库文件、报告期范围和更新时间。
- 图像：不使用装饰性图片，真实数据和图表是唯一视觉主体。

### 4.2 设计原则

- 深色低眩光背景，内容面板使用清晰边界，不使用玻璃拟态和大面积渐变。
- 数字使用等宽或表格数字特性，金额、百分比和排名严格对齐。
- 盈利、正增长使用红色；亏损、负增长使用绿色；零值和缺失使用中性灰。
- 资产负债率等不能简单解释为涨跌好坏的指标使用中性色和风险阈值，不滥用红绿。
- 动效只用于状态变化和筛选结果过渡，支持 `prefers-reduced-motion`。
- 所有颜色、字体、间距、字号、圆角、规则线、时长和缓动均来自 `tokens.css`。
- CSS 首行包含 Hallmark 结构标记和预发自评标记。

## 5. 页面与路由

### 5.1 `/compare` 同行对比首页

默认进入同行对比工作台：

- 共同报告期选择。
- 公司搜索和多选，默认展示全部当前样本公司。
- 指标维度：规模增长、盈利质量、运营效率、偿债能力。
- 比较模式：绝对值、行业中位数指数、行业分位。
- 结论区：只展示由真实数据计算的领先项、落后项和异常项。
- 图表区：规模与增长、利润率与费用率、杠杆与应收账款。
- 同行矩阵：可排序、可筛选，固定表头，支持键盘访问。
- 点击公司名称进入单家公司分析。

不允许将缺失记录绘制为 0。所有同行指标必须使用选中公司的共同报告期。

### 5.2 `/company/:code` 单家公司分析

- 公司搜索和报告期选择。
- 数据口径：累计、单季度、TTM、年度。
- 摘要：营业收入、归母净利润、扣非净利润、毛利率、净利率、资产负债率、应收账款占比、累计 ROE、年化 ROE 估算。
- 盈利能力：收入、毛利润、净利润、扣非净利润和利润率趋势。
- 成长性：同比增长、单季度变化、TTM 变化。
- 费用效率：销售、管理、研发和财务费用率；财务费用为负时显示为财务净收益。
- 资产负债：总资产、总负债、净资产、资产负债率和应收账款。
- 指标说明：公式、单位、来源字段和计算限制。

当前数据库没有现金流量表。页面必须明确显示“当前数据源未提供现金流数据”，不得构造现金流指标。

### 5.3 `/data-quality` 数据质量

- 数据库绝对路径和文件更新时间。
- 正式表结构版本。
- 公司数、报告期范围、利润表和资产负债表记录数。
- 导入批次及成功、警告、失败数量。
- 字段解析失败、缺失、异常范围和期间不一致问题。
- 原始记录 ID 与正式记录的追溯关系。

## 6. 数据标准化设计

### 6.1 原始表策略

保留现有 `利润表temp` 和 `资产负债表temp`。两张表作为网页抓取原始数据，不删除、不重命名、不覆盖历史备份表。

### 6.2 新增正式表

#### `companies`

- `code TEXT PRIMARY KEY`：标准证券代码。以 6、5、9 开头的六位代码使用 `SH` 前缀，其他使用 `SZ` 前缀。
- `raw_code TEXT`：原始表中的代码。
- `name TEXT NOT NULL`
- `market TEXT NOT NULL`
- `industry_name TEXT NULL`：当前数据没有可靠行业细分时保持空值。
- `updated_at TEXT NOT NULL`

#### `import_batches`

- `batch_id TEXT PRIMARY KEY`
- `source_name TEXT NOT NULL`
- `started_at TEXT NOT NULL`
- `completed_at TEXT NULL`
- `status TEXT NOT NULL`
- `raw_row_count INTEGER NOT NULL`
- `normalized_row_count INTEGER NOT NULL`
- `issue_count INTEGER NOT NULL`

#### `income_statements`

- 主键：自增 ID。
- 唯一键：`code + report_period`。
- 报告属性：`report_period`、`report_type`、`currency`。
- 金额字段统一为人民币元的 `INTEGER`。
- 比率字段统一为百分点的 `REAL`，例如 `6.36` 表示 `6.36%`。
- 包含营业收入、营业总成本、营业成本、销售费用、管理费用、财务费用、研发费用、税金及附加、营业利润、利润总额、净利润、持续经营净利润、归母净利润、扣非净利润、利息费用、利息收入、毛利润、毛利率和营收同比增长。
- 追溯字段：`source_record_id`、`import_batch_id`、`collected_at`。

#### `balance_sheets`

- 主键：自增 ID。
- 唯一键：`code + report_period`。
- 金额字段统一为人民币元的 `INTEGER`。
- 包含总资产、总负债、实收资本、资本公积、其他综合收益、盈余公积、未分配利润、少数股东权益和应收账款。
- 追溯字段：`source_record_id`、`import_batch_id`、`collected_at`。

#### `data_quality_issues`

- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `batch_id TEXT NULL`
- `statement_type TEXT NOT NULL`
- `code TEXT NULL`
- `report_period TEXT NULL`
- `field_name TEXT NOT NULL`
- `raw_value TEXT NULL`
- `issue_code TEXT NOT NULL`
- `issue_message TEXT NOT NULL`
- `created_at TEXT NOT NULL`

### 6.3 解析规则

- `亿` 乘以 100,000,000。
- `万` 乘以 10,000。
- 支持千分位、前后空格、百分号和负号。
- `--`、空字符串、`None` 和无法解析内容返回 `NULL`。
- 金额转换后四舍五入到人民币元。
- 百分比去除 `%` 后保留百分点数值，不转换为 0 到 1 的比例。
- 日期必须转换为 `YYYY-MM-DD`。
- 报告类型根据月日映射：03-31 为 Q1、06-30 为 H1、09-30 为 Q3、12-31 为 FY。
- 无法解析的值写入 `data_quality_issues`，不得转换为 0。

### 6.4 写入策略

- Python 入库在同一事务中写入原始表和正式表。
- 正式表使用 `ON CONFLICT(code, report_period) DO UPDATE`。
- 任一正式表写入失败时回滚本次正式数据写入并记录批次失败。
- 原始记录保留抓取文本，正式记录保存标准化数值。
- 修正 Selenium 中“营业成本”错误复用“营业总成本”定位器的问题。

### 6.5 一次性迁移

新增迁移程序，将当前原始表数据回填到正式表：

- 预期迁移 24 家公司。
- 预期利润表 168 条、资产负债表 168 条。
- 保留当前 28 条负财务费用记录，不得归零。
- 浙江震元 2026-03-31 的负净利润必须保持为负数。
- 迁移可重复执行，重复运行不增加重复记录。

## 7. 指标计算规则

### 7.1 报表口径

- Q1 累计值即第一季度单季度值。
- H1 单季度值等于 H1 累计值减 Q1 累计值。
- Q3 单季度值等于 Q3 累计值减 H1 累计值。
- FY 第四季度值等于 FY 累计值减 Q3 累计值。
- 缺少相邻累计期间时返回 `NULL`。
- TTM 为最近四个连续单季度值之和，期间不足时返回 `NULL`。

### 7.2 比率

- 毛利率优先使用标准化源字段；源字段缺失时使用毛利润除以营业收入。
- 净利率使用归母净利润除以营业收入；归母净利润缺失时使用净利润并显示降级说明。
- 资产负债率为总负债除以总资产。
- 应收账款占比为应收账款除以总资产；界面明确分母。
- 累计 ROE 为累计归母净利润除以平均归母净资产的估算值。
- 年化 ROE 根据报告类型使用 4、2、4/3、1 的年化因子，并标注“估算”。
- 平均净资产缺少期初值时返回 `NULL`，不使用期末值替代。

### 7.3 同行对比

- 共同报告期为所有选中公司均存在的最新期间。
- 行业中位数指数以选中样本中位数为 100。
- 分位排名明确样本数量。
- 缺失值不参与中位数和排名。
- 金额差距过大时默认提示切换指数模式，不自动使用对数坐标隐藏差异。

## 8. API 设计

- `GET /api/health`：数据库可读性和模式版本。
- `GET /api/meta`：路径、更新时间、公司数、期间范围和问题数。
- `GET /api/periods`：可用报告期及类型。
- `GET /api/companies`：公司列表和搜索。
- `GET /api/compare`：共同报告期、同行指标、中位数、分位和排序结果。
- `GET /api/companies/:code`：公司概览和可用报告期。
- `GET /api/companies/:code/analysis`：指定口径的趋势、指标和字段说明。
- `GET /api/data-quality`：批次和质量问题摘要。

API 使用统一响应结构，错误必须包含稳定错误码、中文说明、可重试标志和受影响范围。

## 9. 状态与错误处理

- 首次加载显示骨架和实际数据库路径。
- 数据库不存在、不可读、被锁定、正式表缺失或结构版本错误时，不显示业务页面数据。
- 提供重试操作，但不提供模拟数据回退。
- 图表无数据时显示原因和对应数据表。
- 页面筛选条件写入 URL 查询参数。
- 公司选择、报告期和模式可以保存在浏览器本机。
- API 请求取消旧请求，避免快速切换筛选时旧结果覆盖新结果。

## 10. 响应式与无障碍

- `html` 和 `body` 使用 `overflow-x: clip`，不使用全局横向隐藏来掩盖溢出。
- 960px 以下侧栏收起，内容改为单列。
- 640px 以下图表简化标签，对比表进入可控横向滚动或转换为指标列表。
- 实现 320、375、414 和 768px 宽度对应的基础断点规则，但本轮不将移动端视觉验证作为完成阻断条件；最终显示效果由用户手工确认。
- 可点击公司使用真实链接，不使用只有 `click` 的表格行。
- 输入控件具有可见标签，错误信息和控件建立关联。
- 图表包含标题、说明和等价数据表。
- 所有操作支持键盘，焦点环清晰可见。
- 红绿颜色同时配合正负号、文字和图形方向，不以颜色作为唯一信号。
